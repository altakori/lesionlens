## 목적

3차 멘토링의 문제의문을 제품으로 답한다: 병원에 안 들어가는 이유는 모델 성능이 아니라 검증·수가·워크플로우·책임이다. 따라서 앱이 증명해야 할 것은 정확도가 아니라 **재검토 우선순위가 실제 업무량을 줄이는가**와 **전달이 책임 있게 기록되는가**다.

## 비목표

실제 병원 전송, 환자-담당자 매핑, 인증 다중 사용자 서버, PACS/HIS 연동 구현, 실제 SMS 발송, 진단·치료 권고, 의료 데이터나 개인정보를 Notion·외부 worker에 전달하는 일. 연동은 제안서 수준까지만 만든다.

- 수용기준: AI·기본값이 선택지를 미리 채우지 않는다. 선택값이 전송 스냅샷에 불변 저장되고 보낸 사례에서 그대로 재현된다. 기존 메모 폐기 확인·초안 유지 규칙과 충돌하지 않는다. 키보드·포커스·접근성 회귀 없음. 320px에서 주 행동 가림 없음.

### P0-2 AI 노출 전 판단의 분리 기록 (3차 멘토링 C5·C7)

- **상태(2026-09-27): 전체 강제 구현 보류.** 재검토 목록에 모델·불일치 신호가 이미 노출되므로 상세 화면만 잠그는 것으로는 독립적인 사전 판단이 되지 않는다. 잠금 대신 사전 소견·노출·채택 필드를 저장 구조에 먼저 넣고, 강제는 09-29 MD 관찰에서 막힌 행동이 확인된 뒤 판단한다.

- **상태 갱신(2026-09-27 심야): 기록 항목만 비강제로 구현.** 브랜치 `feat/pre-opinion-record`(`0537656`, worktree `IRB 대회/LesionLens_preopinion`)에 사전 의견 3종(재확인 필요 / 재확인 불필요 / 판단 유보)과 "미작성으로 되돌리기"를 추가했다. 기본은 미작성, 강제는 없고, 잘못된 값은 전송 전에 실패시키고 기록을 남기지 않는다. 라벨은 "사전 의견(참고)"이고 화면에 "이 창은 재검토 목록의 모델 불일치 신호를 이미 표시한다"는 한계를 그대로 적는다 — 즉 이 구현은 수용기준의 독립적 사전 판단을 만족하지 않으며, 만족 여부는 강제 도입 전까지 보류다. 채택 여부(AI 제안과 최종 소견의 일치) 필드는 넣지 않았다. 검증: `test:unit` **68/68**, 기존 것(4173)과 개선 것(4174)을 동시에 띄워 브라우저 테스트가 양쪽 모두 통과.
- 동기: AI를 먼저 보면 독립 판단과 AI 영향 판단이 한 기록으로 섞인다. 책임은 서명 판독자에게 남는다(Acad Radiol 2026, DOI 10.1016/j.acra.2026.09.007). AI 표시에 판단이 번복되는 실험 관측(Radiography 2026, DOI 10.1016/j.radi.2026.103577).
- 변경: 재검토 카드의 상태 전이를 `(미검토) → 사전 소견 → AI 후보 노출 → 최종 소견/전송 또는 확인함`으로 확장. 사전 소견 체크박스는 `재확인 필요 / 불필요 / 판단 유보`, AI 후보·근거는 그 다음에 노출. `md-core.js`의 저장 스키마에 상태·시각·AI 노출 여부를 추가하고, 채택 여부(AI 제안과 최종 소견이 같은지)를 별도 필드로 저장.
- 수용기준: 사전 소견을 채우지 않으면 AI 후보 영역이 열리지 않는다(단, 설정으로 해제 가능하되 기본은 강제). 정정 시 원본 사전 소견이 보존되고 수정 이력이 남는다. AI가 사전 소견의 기본값이 되지 않는다. 화면과 문서 양쪽에 책임 문구 유지. 과거 저장 데이터와 호환(없으면 `미기록`으로 표시, 추측 채움 금지).
- 검증: 상태 전이 단위 테스트(정정·undo·새로고침·동시 저장 포함), 브라우저에서 사전→사후 흐름과 스크린리더 라벨, 스키마 마이그레이션 테스트.

  - 시리즈 항목은 CT만 마운트(`['ct']`)하고 `defaultSlice`로 연다. 모델 오버레이를 얹지 않아 다른 검사의 예측을 이 환자 비교처럼 보이지 않게 했다.

- 전송 화면에 프로토콜별 사전확인 체크리스트, 주치의 화면에 `조직검사 프로토콜 보기` 토글과 `md-record-biopsy-protocol` 라인을 추가했다. 체크리스트는 용량·약물·시간 수치를 적지 않고 `이 병원의 실제 프로토콜 문서 아님`, `기관 확인 필요`로 마무리한다(수치 금지 자체를 테스트로 고정).
- 주치의 화면에 `md-record-series`를 추가했다. 이 서버가 게시하는 검사는 CT만 열리고(현재 데이터 연결 표시), 게시하지 않은 LL-CT-001은 이유 문구로 fail-closed. 기존 `md-prior-study` 섹션은 새 기록에서는 시리즈에 흡수되고 `series`가 없는 옛 기록에만 남는다.

### 발표 전 주의
- 시리즈는 데모 구성이다. 발표에서는 "환자 추적을 구현했다"가 아니라 "시리즈 제시 흐름을 구현했고 실제 환자 매칭은 검증하지 않았다"로 말한다.
- 프로토콜 체크리스트는 일반 안내 문구이고 병원 문서가 아니다. 실제 도입 검토 단계에서는 기관 프로토콜 문서로 교체해야 하며, M6 보안·기관 정책 항목과 함께 다룬다.
