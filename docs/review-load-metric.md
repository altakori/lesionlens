# 검사당 추가 검토 후보 수 지표 계약

- 작성 2026-09-27 · 소유: LesionLens_MVP · 관련: 3차 멘토링 D3, 개발계획 P0-4
- 상태: 탐색 측정용 계약 확정. 확정 지표로 발표하려면 코호트를 늘려 재측정한다.

## 1. 왜 필요한가

"우선순위가 업무를 줄인다"는 주장의 1차 지표는 검사당 검토 후보 수다. 중복 제거 기준과
분모를 먼저 고정하지 않으면 후보 개수가 모델 수에 따라 부풀려지고, 비교 불가능해진다.

## 2. 정의(고정)

| 항목 | 정의 |
| --- | --- |
| 단위 | 검사(CT study) 1건 |
| 분모 | 후보 증거(evidence)가 있는 검사 수. 증거가 없는 검사는 0으로 채우지 않고 결측으로 별도 계상 |
| 후보 | 한 모델이 지목한 3D 연결성분 1개(26방향 연결) |
| 중복 제거 | 서로 다른 모델의 후보가 기록된 매칭 기준을 충족하면 같은 위치로 보고 union-find 로 병합 |
| 매칭 기준 | intersection / min(component voxels) >= 0.1 (evidence.json rules.match) |
| 고유 후보 | 병합 후 남은 그룹 수 (중복 제거 후 검사당 검토 후보 수) |
| 추가 후보 | 어느 모델 후보와도 짝지어지지 않은 후보. 단일 모델 흐름에서는 발견 확률이 낮은 후보 |
| 작음 | 추가 후보 중 reasons 에 kind=unmatched 이고 smallAdditional=true 로 기록된 후보(0초과 1mL 미만) |

병합은 전이적으로 적용한다. A-B, B-C 가 짝지면 A-B-C 는 같은 위치 1개로 계상한다.
매칭 변은 데이터 생성 시점의 voxel 집합으로 계산된 기록을 그대로 쓰며, 이 측정에서 다시 계산하지 않는다.

## 3. 로컬 시연 코호트 탐색 결과 (2026-09-27)

- 입력: `data/model_compare/evidence.json` sha256 3f747c6e9d4a297c… (앞 16자리)
- 분모 4건, 결측 1건(case_045 · 세 모델 예측 모두 없음 → 앱에서는 "AI 비교 자료 없음" 상태)

| 검사 | 모델별 후보(baseline/cappyv2/cp050) | 중복 제거 후 고유 | 추가 후보 | 그중 작음 |
| --- | --- | --- | --- | --- |
| case_000 | 9 / 9 / 10 | 10 | 1 | 1 |
| case_001 | 13 / 13 / 13 | 13 | 1 | 1 |
| case_035 | 7 / 11 / 16 | 17 | 10 | 6 |
| case_048 | 2 / 2 / 3 | 3 | 1 | 1 |

- 고유 후보: 분자 43 / 분모 4 = 평균 10.75, 중간값 11.5, 최소 3, 최대 17, Q1 8.25, Q3 14.0
- 추가 후보: 분자 13 / 분모 4 = 평균 3.25, **중간값 1.0**, 최소 1, 최대 10, Q1 1.0, Q3 3.25
- 추가 후보 중 작음: 분자 9 / 분모 4 = 평균 2.25, 중간값 1.0, 최대 6
- 참고 단일 모델 최다 후보: 중간값 11.5, 최대 16 (중복 제거 전 후보 부하와 비교용)

읽는 법: 추가 후보 중간값은 1건으로 기준안(중간값 <=3)을 만족한다. 다만 case_035 한 검사가
10건(그중 작음 6건)으로 평균을 3.25까지 올린다. 후보 부하가 검사 사이에 고르지 않으므로
검토 부담은 평균이 아니라 검사별 분포로 보고한다.

## 4. 이 수치로 말하지 않는 것

- 업무시간 절감·의료진 부담 감소: 시간 지표는 규칙(시작·종료·로딩·자리비움·중단·결측) 확정 후 탐색 수집한다.
- 임상 민감도·위양성: 정답 병변 대비 맞춧도를 재지 않았다. 후보는 의료진이 판정한 병변 개수가 아니다.
- 일반화: 로컬 시연용 선별 5건(증거 4건)이며 27건 held-out 코호트가 아니다.
- 모델 성능 우월성: 모델 간 검출 성능 비교가 아니라 검토 부하 계수다.

## 5. 재현

```
python scripts/evaluation/review_load_metric.py --evidence data/model_compare/evidence.json --out work/review-load-20260927
```

출력: `work/review-load-20260927/result.json`(사례 ID·분자·분모·규칙·입력 sha256), `report.md`.
표준 라이브러리만 사용하며 네트워크와 원시 마스크를 쓰지 않는다.

검증: 병합 그룹 수와 미짝 후보를 독립 구현(BFS 인접리스트 탐색)으로 재계산해 4건 모두
union-find 결과와 일치함을 확인했다(2026-09-27). 결측 1건은 값이 0 이 아니라 제외 사유로 기록된다.
