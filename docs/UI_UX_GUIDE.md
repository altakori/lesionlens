# LesionLens UI/UX 작업 기준

UI 변경 전 반드시 읽는다. 사용자 요구: 기능을 늘리기보다 난잡한 화면을 정리하고, 무엇을 먼저 확인할지 즉시 이해할 수 있게 한다.

## 근거 자료와 적용
- 토스, 8가지 라이팅 원칙: https://toss.tech/article/8-writing-principles-of-toss — 명확함·간결함·중복 문장 제거·다음 행동 예측. 제목을 설명문으로 반복하지 않는다.
- NN/g, Progressive Disclosure: https://www.nngroup.com/articles/progressive-disclosure/ — 핵심 선택을 먼저, 드문 옵션·고급 정보를 요청할 때 공개. 숨긴 기능의 입구는 명확하게 유지한다.
- WCAG 2.2 target size: https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html — 최소 목표 크기·간격을 고려한다. 이 프로젝트는 주요 조작 44px를 목표로 한다(프로젝트 기준이며 WCAG AA 최소값과 같다는 뜻이 아님).
- 이전 토스·카카오 조사: easy-korean-comparison-design.md. 카카오톡의 익숙한 목록/아이콘은 참고 방향일 뿐, 임상 UI 효과가 검증됐다는 근거가 아니다.

## 2차 멘토링·MD 피드백 — 최신 기준
최신 기능 계약과 근거는 `md-feedback-task.md`다. 아래 과거 지침과 충돌하면 최신 계약을 우선한다.

1. 재검토 CT 목록이 첫 화면이다. CT ID와 실제 재검토 이유를 굵게 표시하고, 최대·전체 후보 부피와 3D 후보 수·측정 모델은 보조 정보로 둔다.
2. ‘모델 간 불일치’·‘작은 추가 후보’를 중심으로 실제 후보 대응 근거를 표시한다. GT 크기·개수 탐색 그룹을 기본 추천으로 쓰지 않는다. 정렬·매칭·작은 후보 기준은 임상 검증 전 잠정 규칙이다.
3. 같은 카드의 AI 소견·Radiomics는 펼쳐 보기. CT 비교를 열면 핵심 한 줄만 남긴다. 다른 데이터셋의 Radiomics를 같은 CT의 결과로 연결하지 않는다.
4. CT는 같은 화면에서 2×2로 GT / CAPPY2 current / CAPPY2 050 / Baseline을 비교한다. 슬라이스·확대 위치·대비를 공유하고 결측은 결측으로 둔다. 일반 검토에는 모달을 쓰지 않는다.
5. 상태 필터는 미검토 / 검토 완료 / 전송됨 / 전체. 숨김은 삭제가 아니며 완료는 정상 판정이 아니다.
6. 주치의에게 전송하기는 문구를 유지하고 전송 모달만 사용한다. 실제 환자-담당자 연결이 없으면 실제 전송 금지. 병리학과는 수신 대상이 아니다.
7. 병원 모델 설정은 우상단 보조 영역. 통계·연구 자료는 후순위, 기능의 중요도를 같은 강조로 처리하지 않는다.
8. 데스크톱에서 목록은 넓은 한 열, 확대 뷰어는 카드 아래 전체 폭. 모바일에서도 문구를 작은 글자로 줄이지 않고 도구 줄바꿈과 2×2/좁은 화면 세로 배치를 사용한다.

## 화면 규칙
- 추천과 같은 내용의 소개 말풍선·큰 통계판을 중복 배치하지 않는다.
- 한 영역에 주 행동 하나. 카드의 CT 버튼을 강조하고 수동 우선 지정은 보조 처리한다.
- 순위 비교는 여러 열 카드보다 정렬된 한 열 목록을 기본으로 한다.
- 한 사례에서 순위·검토 등급을 여러 크고 화려한 배지로 반복하지 않는다.
- 색상은 중립 배경 + 보라 주 행동 + 황갈색 우선 재검토. 빨강/초록으로 응급/안전을 암시하지 않는다.
- X·눈·전송 모달의 종이비행기는 아이콘 단독 사용 가능. 툴팁·접근성 이름·44px 조작 영역을 제공한다. ‘주치의에게 전송하기’ 진입은 문구를 유지한다. 장식용 이모지는 반복하지 않는다.
- 다중 태그 기능을 제거하지 않는다. 필터 입구와 현재 선택 상태는 확인 가능해야 한다.
- 임상 응급도 미평가와 데이터 부재는 감추거나 정상으로 바꾸지 않는다. 각 카드의 짧은 상태는 유지하고 긴 설명만 상세로 옮길 수 있다.
- GT/모델 차이·연결 성분을 임상 진단·전이·응급도라고 표현하지 않는다.
- 기능을 CSS로 숨겨 테스트만 통과시키지 않는다. 접은 정보는 명확한 사용자 조작으로 열려야 한다.

## 변경 절차
1. 현재 화면에서 중복·경쟁하는 강조·불필요한 이동을 적는다.
2. 기존 ID/동작/저장/접근성 계약을 유지하고 HTML/CSS를 정리한다.
3. 비시각 로직 변경은 승인된 Codex worker 경로를 사용한다.
4. npm test 및 npm run test:browser 실행. 접힘 도입 시 테스트는 먼저 펼치는 실제 동작을 하도록 수정하고 assertion을 약화하지 않는다.
5. 1440/768/390/320px에서 가로 넘침, 다음 CT 가시성, 접힘 키보드, 모델 전환, 닫기 포커스를 확인한다.
6. screenshots를 qa/ 하위에 보존한다. 캡처·DOM 기하 검사와 사람이/모델이 실제 이미지를 본 시각 평가를 구분한다.
7. 최종 보고는 변경·실제 검증·남은 제한만. 임상 성능이나 사용자 평가를 검증했다고 과장하지 않는다.


## 간결화 기준 — 반복 피드백 반영
- 토스의 간결한 문구와 카카오톡의 일정한 목록 구조를 참고한다. 브랜드 복제보다 다음 행동과 읽는 위치의 일관성이 우선이다.
- 기본 카드에는 사례명, 순위 한 줄, 이유 한 줄, 다중 태그, 짧은 미평가 상태, CT 버튼을 둔다. 같은 등급을 큰 제목으로 반복하지 않는다.
- 확인 행동은 짧은 한 줄을 유지하고, 자료 수·계산값·긴 출처는 '이유와 측정값 자세히'에 배치한다. 삭제하거나 접근 불가능하게 숨기지 않는다.
- 병원 모델 준비·검증 설명은 CT 목록 뒤에 둔다. 보조 패널을 주 목록 위에 계속 추가하지 않는다.
- 글자를 작게 만들어 밀도를 해결하지 않는다. 문장 중복 제거→위치 조정→여백 순으로 개선한다.
- 기본/펼침 두 상태와 모바일·키보드·기존 기능을 함께 검사한다.

- 이전 크기·개수 그룹 강조는 2차 MD 흐름에서 대체되었다. 재검토 이유를 먼저 표시하고 숫자·부피는 보조 정보로 둔다. 자료가 없으면 이유 미산출을 정직하게 표시한다.
- 같은 우선 그룹의 ID순은 기술적 동률 처리이지 임상 우열이 아니다. 모델 일치·검토 완료·신호 없음은 정상 또는 안전을 뜻하지 않는다.
