## 한 문장 결론

LesionLens를 곧바로 기능 확장하지 않고, **“추가 확인 가치가 큰 검사를 의료진이 먼저 볼 수 있게 한다”**는 목적 아래 실제 발생 가능한 사례를 먼저 넓게 나열하고, 분류 기준과 각 화면 요소의 목적을 세운 뒤 UI를 압축한다.

## 멘토 핵심 피드백

### 1. 서비스 목적과 ‘꼭 먼저 볼 사례’의 기준을 먼저 정한다

- 현재 설명은 개발자의 배경지식을 전제로 해 외부 심사자가 이해하기 어렵다. 시작 배경과 앞단의 맥락을 보충하고, 심사 기준이 공개되면 그 기준에 맞춰 문서를 다시 구성해야 한다. *(04:31~07:24, 변환본 111~150행)*
- “먼저 볼 수 있게”만으로는 부족하다. 반드시 확인해야 하는지, 언젠가 확인하면 되는지에 따라 데이터 흐름·정렬·화면 구성이 달라진다. *(58:02~01:00:19, 843~870행)*
- 회의에서 잠정 합의한 목적은 “의료진이 추가 확인 가치가 큰 검사를 먼저 보고, 나머지는 누락하지 않은 채 일반 순서로 검토하도록 돕는 것”이다. 이에 맞춰 ‘꼭 봐야 하는 것’의 기준을 구체화해야 한다. *(01:01:02~01:01:45, 875~888행)*

### 2. 가능한 현장 사례를 먼저 넓게 적고 분류 기준을 세운다

- 위급도·정확도 같은 상위 범주를 먼저 고정하면 새 사례가 들어왔을 때 어디에 배치할지 모호해진다. 실제 발생 가능한 사례를 최대한 나열한 뒤, 공통 기준으로 묶어야 한다. *(28:30~30:08, 447~462행)*
- 각 사례가 왜 선택됐는지 태그나 근거로 표시하고, 확률·수치가 실제 사용자 판단에 중요할 때만 노출해야 한다. *(30:34~31:06, 464~480행)*
- 다음 멘토링 전 가장 우선할 작업은 사례 목록과 분류 기준이다. *(40:34~41:00, 584~590행; 01:01:53~01:02:29, 890~900행)*

### 3. 모든 화면 영역과 조작에는 한 줄 목적이 있어야 한다

- 대기열, 상세 화면, 버튼, 정렬·필터 각각이 사용자가 무엇을 하도록 돕는지 명확해야 한다. 목적에 따라 정렬 방식과 정보량이 달라진다. *(32:05~35:30, 485~525행)*
- 의료 현장에서 통용되는 아이콘인지 확인되지 않았다면 아이콘만 두지 말고 텍스트 라벨을 함께 제공하고, 이후 사용자 검토로 축약 여부를 결정한다. *(36:08~37:16, 527~537행)*
- 기존 ‘상위 10/20/30% 검토량’은 실제 대기열 조작인지 연구 평가용 operating point인지 불명확하다. 실제 사용 화면에서는 숨김보다 우선순위 정렬이 목적에 더 맞을 수 있다. *(37:16~40:10, 539~570행)*

### 4. 모델·데이터 신뢰 근거와 한계를 짧고 정확하게 제시한다

- 어떤 데이터와 검증을 바탕으로 모델 출력을 보여주는지, 왜 이 선택을 했는지 근거가 필요하다. 적은 데이터로 확정적 판단을 한 것처럼 보이면 신뢰성 질문이 생긴다. *(18:13~21:38, 299~345행)*
- “가능한 데이터를 모두 썼다”는 식의 표현은 피한다. 공개 데이터 범위, 라벨 부족, 외부·기관 데이터 접근에 필요한 승인과 검증 한계를 분리해 적는다. *(19:38~20:53, 323~339행)*
- 모델 튜닝과 기관별 학습은 데이터와 기술 조건이 준비된 뒤 별도 논의한다. 4주 MVP의 핵심 화면 범위와 섞지 않는다. *(21:54~25:20, 347~390행)*

### 5. 사회적 가치는 제출 스토리에서 연결하되 앱 기능보다 앞세우지 않는다

- 심사 기준은 아직 공개되지 않았으므로 주최 측에 확인해야 한다. 공개되면 대회 목적·콘셉트·심사 기준에 문서를 맞춘다. *(47:28~49:34, 713~750행)*
- 사회적 가치는 단순 수익화보다 조기 추가 확인, 제한된 판독 자원의 효율적 배분, 환자에게 돌아갈 잠재적 이익으로 설명한다. 다만 현재 MVP가 사망 감소나 격차 완화를 입증한 것처럼 쓰지 않는다. *(49:34~54:40, 752~801행)*
- 서비스 자체를 사회적 가치 문구에 억지로 맞추는 것은 우선순위가 낮다. 먼저 쓸 만한 서비스를 만들고 제출 소개·배경·기대효과에서 스토리텔링한다. *(54:06~54:40, 791~801행)*

## 확정한 제품 결정

1. **1차 사용자:** 다수의 간 CT를 검토하는 영상의학과 의료진. 의료영상 QA 담당자는 같은 근거를 확인하는 보조 사용자로 둔다.
2. **서비스 목적:** 전체 검사를 없애거나 진단하는 것이 아니라, 추가 확인 가치가 큰 검사를 대기열 상단에 정렬하고 그 이유를 설명한다.
3. **기본 대기열:** 모든 사례를 유지하고 ‘추가 확인 가치 순’으로 정렬한다. 필터는 화면 탐색용이며 미표시 사례가 안전하다는 뜻이 아니다. 여러 신호가 겹치면 작은 후보·모델 불일치는 `먼저 확인`, 기술적 영상 품질 점검이 우선인 사례는 `품질 확인`으로 대표 라벨을 정하고 상세 근거에는 모든 신호를 남긴다.
4. **연구 평가와 사용자 조작 분리:** 상위 10/20/30%는 held-out 평가의 operating point로 유지하되, 실제 대기열을 잘라 숨기는 기본 조작으로 쓰지 않는다.
5. **표현 원칙:** ‘위급도’, ‘완치 가능’, ‘전이 확률’처럼 현재 입력으로 계산하지 못하는 임상 표현을 쓰지 않는다. `먼저 확인`, `품질 확인`, `일반 순서`와 구체적 신호를 사용한다.
6. **사례별 설명:** 모델 불일치, 작은 병변 후보, 영상 품질 중 해당 근거를 텍스트 태그와 상세 설명으로 표시한다. 신호 점수는 합성 데모 값이며 임상 확률이 아님을 명시한다.
7. **사회적 가치 경계:** ‘제한된 재검토 시간을 근거 기반으로 배분할 가능성’을 검증 대상으로 삼고, 생존 향상·의료격차 완화는 후속 가설로만 둔다.

## 보류 사항

- `먼저 확인`으로 분류할 임상적 기준은 의료진 검토 전 확정하지 않는다.
- 전이 가능성·완치 가능성·응급도는 현재 모델 출력만으로 제시하지 않는다.
- 실제 의료진 사용성, 기관별 재학습·보정, 원내 workflow 통합은 4주 MVP 밖이다.
- 심사 기준과 최종 제출 형식은 주최 측 공식 안내를 확인한 뒤 문서 구조에 반영한다.
