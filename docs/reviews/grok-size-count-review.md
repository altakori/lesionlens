**판정:** 합의 범위(내부 리뷰 우선, 검증된 응급 트리아지 아님) 안에서도 **사용자 요청 미충족**. 기본 큐는 ‘크기 AND 다발’이 아니라 **최대 단일 GT 성분 부피 내림의 사전식 정렬**이다. 개수는 태그에 보이나 현재 5례 순서를 바꾸지 않는다. 헤더·카드는 옛 AI 불일치 체계와 공존한다. **임상 사용·병원 도입 준비 아님.** 본 평가는 화면·Notion·코드·영상을 보지 않은 **부모 관찰 기반**이며 독립 시각·임상 검사가 아니다.

**증거 계층:** 사실=제공된 관찰만. 추론=요청·일관성 해석. 미지=최신 Notion, 실제 병변/직경, 가독성, 임상 유용성.

## 크기+개수 요청 vs 실제 정렬

**사실.** 기본 순서: 수동 핀 → GT 있음 → 최대 단일 GT 성분 부피 내림 → **부피가 완전히 같을 때만** 성분 수 내림 → ID. 총부담 합산 없음. 부피가 다르면 개수는 무시. 비핀 순서(최대 mL/개수): 048=81.8704759/4, 035=10.767/3, 045=4.539/1, 001=4.336176/12, 000=2.682037/11. **개수는 이 다섯 순서에 영향 없음.** 001(12개)이 045(1개, 예측 없음)보다 아래. 045는 모델 예측이 없어도 GT가 있어 3위. 표시는 소수 2자리, 순위는 정확 부피. GT는 26연결 성분 부피/개수이며 확정 병변·측정 직경이 아님. AASLD HCC 3/5cm·Milan은 혼합/미상 종양에 **미적용**. 임상 컷포인트 주장 없음. 크기 우선은 저자 선택 미검증 정책.

**추론.** 요청(크기 **AND** 다발, 우선사유 태그≠일반 태그, 토스/카카오식 짧은 UI)은 정렬 차원에서 **미이행**. 실효는 lexicographic volume-only. 최대 성분이 임상 긴급과 같다는 근거 없음(제공 진술과 일치). 가중치를 임상 진실로 창작하지 않는다.

**대안(사용자/MD가 고를 것, 리뷰어가 역치를 정하지 않음):**  
(1) 현행 사전식을 **사실 그대로** 고정(“개수=완전 동률만”).  
(2) 최대부피 / 개수 / ID를 **별 토글**, 합성 점수 없음.  
(3) 부피↑이면서 개수↑만 강조하고 전순서 포기.  
(4) 기본은 ID, 사람이 핀.  
GT 없는 신규 CT에는 이 큐를 **그대로 적용할 수 없음**.

## 발견 (최대 7)

**F1. 다발이 순위에 안 들어감**  
증거: 5례 부피 모두 상이 → count 미사용. 001 12개 < 045 1개.  
최소수정: 최상단에 실제 규칙 한 줄. AND를 원하면 MD가 키를 선택(가중 창작 금지).  
수용: 헤더만 읽고 048>001이 재현되고, 001이 다발만으로 승격되지 않음이 명시.

**F2. 헤더가 옛 AI 밴드**  
증거: ‘AI 차이 우선검토1건 / 나머지 확인 전4건 / 완료0 / 응급 미평가5’, 불일치 밴드 0. 기본 큐는 크기.  
최소수정: 헤더 건수를 실제 기본 정책과 같은 축으로 맞추거나 밴드 헤더 삭제.  
수용: 헤더·리스트·히어로가 같은 한 문장 정책을 가리킴.

**F3. 카드에 추론 체계가 둘**  
증거: 히어로 이유는 반올림 GT 크기/개수. 048은 AI 개수 다름·경계/작은 GT 검사, 045는 예측 확보. 형태 섹션(노황갈)과 중립 칩은 분리돼 있으나 권고 문장은 일반태그 파생.  
최소수정: 우선사유=형태 섹션만. 일반태그 문장은 제거 또는 ‘정렬 이유 아님’.  
수용: ‘왜 지금 보나’가 부피/개수/핀 외 권고와 충돌하지 않음.

**F4. 짧은 UI 미달**  
증거: 048 행에 id, CT244장, 전체대기열 1번째 크기개수GT, 순위근거, 81.87mL, 4개, 규칙 공개, 응급미평가, AI표시개수다름, 경계 지시, 칩 4, details, 상태, 핀/CT. 부모 측정 데스크톱 ~340px / 모바일 ~650px(이전 범위). 스크린샷 미열람, 미감 단정 안 함.  
추론: 토스/카카오식 짧은 스캔이 아님.  
최소수정: 행 1줄=ID+최대mL+개수+응급미평가+핀. 나머지 details.  
수용: 순위 이유가 한눈에 3요소 이내.

**F5. 문서 복수 권위**  
증거: README 상단 크기우선 vs 하단 구 AI 기본 문단(과거 스냅샷). Notion은 **이번 평가에서 미확인**. 이전 3례·272 vs 5례·640 불일치는 과거 갱신만 보고됨. 지금 동기화됐다고 단정하지 않음.  
최소수정: 기본 정렬 문단 하나만. Notion 동기 주장 금지.  
수용: AGENTS·README·UI/리뷰 가이드가 동일 규칙.

**F6. GT 의존과 045**  
증거: 045 예측 없음에도 GT로 3위. 성분≠확정 병변.  
최소수정: GT/예측 공백을 우선 섹션에. 히어로 범위에 “GT 없는 CT에 이 큐 불가”.  
수용: 예측 공백이 크기 순위와 혼동되지 않음.

**F7. 유틸리티 근거 없음 — 숨기지 말 것**  
증거: 정상/급성/응급 코호트 없음, 순위 vs 무작위 없음, 임상의 유용성·병리 역할 검증 없음. 소프트웨어: Node24·Chrome14 통과, Python21 pass, Windows symlink skip 1 — **스모크이지 유용성 검증 아님**. 병원 모델 패널은 UI만, 컨트롤 7 비활성, 업로드/학습/추론/저장/배포·저장 변이 **미구현·미시험**.  
최소수정: 연구계약·의료주장 변경 없음. 공백을 제품 언어에 유지.  
수용: 해커톤 리뷰 도구로만 자칭.

## 우선 태그 vs 일반 태그, 헤더/히어로/리스트

**사실.** 매행 형태 섹션(전역 서수, GT 출처, 최대부피/개수)과 중립 일반 칩 분리는 있다. ‘응급 소견 미평가’ 상시. 긴 규칙은 details. 히어로는 리스트 필터/정렬과 무관하게 **전체 부담 큐의 첫 미검토**, 범위 문구 있음, 완료 시 전진, 핀 우선, 브라우저 로컬. 레거시 AI 차이 정렬은 details에 잔존.

**추론.** 색 분리 ≠ 정보 계층. 우선태그가 ‘왜 이 순인가’를 독점하지 못하고, 일반태그가 권고 문장과 헤더 밴드로 경쟁한다. 히어로가 필터를 무시함은 명시됐으나, 헤더가 AI 건수를 말하면 히어로가 AI 우선으로 오해되기 쉽다. 혼합은 구현 버그라기보다 **정책 두 개를 동시에 보여 주는 설계**.

**미지.** 실제 스캔 속도, 대비, 토스/카카오 유사성.
