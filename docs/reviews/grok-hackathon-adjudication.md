# Grok 해커톤 검토 — 부모 판정

## 결론
Grok4.6 단일 응답 HTTP200, 원문 재조회 완료. 예시 점수54/100(공식 루브릭·수상확률 아님). 노션147블록 전체 재조회, 현재 개발 문서 및 live Chrome DOM 대조. 앱/노션은 변경하지 않음. 원본 데이터·개인정보·비공개 코드·스크린샷은 외부 전달하지 않음.

## 채택
- N2/F1: 노션6·11절 현재 구현은 여전히3사례272장, 신규기능 미구현·체크박스 미완. 실제5사례640장/3모델4사례/다음사례추천·자동순위와 불일치. 기능완료 과장이 아니라 최신화 누락.
- G3: 로컬 MD요구문서 역시 미완 체크리스트. 요구사항/현재구현/계획의 명확한 소유 문서와 revision 연결 필요.
- F2: GT기반 feature가 우선순위band에 개입. 새 CT에서 같은 제품이 동작한다고 주장할 수 없음. 단, '데이터 누수'가 실증된 것은 아님; 현재는 GT의존 시연과 추론용 순위 분리 문제.
- F3: 임계값은 임시. 이미 상세·규칙 문서에서 미검증을 명시하므로 '문헌이 임상적으로 보증한다고 앱이 주장함'은 확인되지 않음. 오독 위험 개선 제안으로 채택.
- F4/5: 한 사례의 유사한 순위 라벨 반복,10필터·상세 문구로 인한 밀도. 부모 live DOM 확인. 미학/사용자 이해도 자체는 이번 검토로 검증하지 못함. 필터 접힘 제목 미완은 알려진 제한.
- F6: Notion연구계획 직경mm·2모델/단독후보/경계·품질 vs 현재mL·3모델/GT연결요소/절편점유 차이. 연구계약을 앱에 맞춰 임의로 바꾸지 말고 서로 다른 범위를 표로 명시.
- F7/F8:5개 선택양성사례로 정상·공통실패 일반화 불가, 병리 역할 미검증. 사용자 삭제가 아니라 실제 역할 확인 필요.

## 기각·수정
- '결측 랭킹은 결함 아님': 단정 기각. case045가 null점수로 후순위가 되는 구현은 맞지만, 미처리/예측없음을 뒤로 보내는 운영정책이 적절한지는 미검증. 결측 별도 업무목록/수동처리 우선정책 검증 필요. 낮은 위험으로 표기하지 않은 것은 장점일 뿐 정책타당성 증거가 아님.
- 병리 역할 예시 'GT/절제맥락 대조': 현재 조직·절제자료 없음. 현 기능이나 합의된 역할로 채택하지 않음.
- GT의존을 'GT누수'라고 부름: 데이터 분리·평가실험을 검토한 것이 아니므로 확정적 누수 판정은 부적절.
- 순위연구/이해도실험을 모두 '선택'으로 분류: 제한된 시연 제출은 가능하지만 우선순위 유용성을 주장하는 데는 반드시 필요한 근거다. 기능완료와 제품가치 검증을 분리해야 함.
- 필터0건 숨김과 카드태그 최소화: 자동 채택하지 않음. 기능발견성과 사용자 다중태그 요구를 유지하고 접기/묶기 방향으로 검토.
- 비주얼 점수8/15는 DOM/설명 기반의 주관적 정보구조 평가. 이미지 실견에 기반한 미학평가나 사용자실험 점수 아님.

2. GT대조 시연 vs 모델만 사용하는 순위 분리 계약; 동일검토량 무작위/단순불일치 baseline 대비 독립 평가 설계. 이번5사례로 임계값 튜닝·일반화 성능 주장 금지.
3. 일반인 평가자/MD 대상 짧은 과제: 우선사례 선택→이유 설명→CT 비교. 오해·시간을 직접 측정. 역할/결측처리 정책 확인.
