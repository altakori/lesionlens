# 적대적 제품·워크플로·UX 검토 (비임상 검증)

본 검토는 제공된 요약 증거(M1, N1, N2, A1–A3)만 사용한다. 앱 조작·Notion 열람·스크린샷 판독을 주장하지 않는다. 임상 효능·구매 수요·수용성을 측정하지 않았다.

---

## (1) 총평: 약속된 우선순위 서비스 대비 현재 산출물

**확인된 불일치.** 현재 산출물은 **데모용 정적 CT/GT 브라우저**다. 약속된 산출물은 **근거가 있는 검토 우선순위 큐**다(N1). 둘은 같은 제품이 아니다.

| 구분 | 현재 산출물 | 약속된 서비스 |
|---|---|---|
| 역할 | 파일 브라우저 + 로컬 검토 토글 | 합리적 우선순위 큐 |
| 사용자 | 불특정 데모 관람자 | 영상의학 MD, 병리 MD(업무 미검증) |
| 진입 | 자동 뷰어, 카테고리 없음 | 카드·카테고리 후 온디맨드 CT |
| 근거 | GT 전체 종양 부피(mL) 정렬 | 측정된 크기/개수/분포 + 순위 이유 |
| 모델 | 없음 | 배포 모델 우선순위와 GT 브라우징은 구분해야 함 |
| 상태 | 신워크플로 미구현(N1) | 계획서의 “최신 승인 요구” |

**프로토타입 / 발표물 / 실제 임상 사용을 섞지 말 것.**

- **프로토타입(경쟁·내부):** 3건 공개 LiTS 양성례, 픽셀·방향·해시 정합성은 신뢰성 점검일 뿐 효용 검증이 아니다(A2). 이 수준이면 “데이터셋 뷰어 데모”로 부르는 것이 정직하다.
- **발표물:** 제목「영상 검토」, 부제「사례를 선택하고 CT와 종양 주석을 함께 확인하세요」(A1)는 멘토가 경고한 소셜임팩트 서사보다도 한 단계 이전인 **뷰어 사용 설명**이다. 우선순위 서비스로 읽히지 않는다.
- **실제 임상 사용:** 인증·감사추적 없음, 로컬 브라우저 persistence, PACS 없음, 음성/실패/정상 코호트 없음, 고정 W400/L50, 모델·불확실성 없음(A1–A2). **임상 사용 후보가 아니다.** 병원급 완제품을 이 단계에서 요구하지는 않는다. 그러나 “우선 검토 큐”라는 제품 주장은 현재 증거와 정면 충돌한다.

**명시적 도전.**

1. GT에서 크기/개수/분포를 파생하는 것만으로 **전향적 우선순위**가 증명되지 않는다. GT는 이미 정답 마스크다. 배포 시 의사는 GT를 보지 못한 채 모델을 상대한다(N1: GT 브라우징 ≠ 배포 모델 우선순위). 부피 정렬은 “이미 알고 있는 병변을 큰 것부터 본다”이지 “먼저 봐야 할 미지의 케이스를 고른다”가 아니다.
2. 치유가능성·전이·긴급도 등 **임상 플레이스홀더를 전부 노출하는 것은 유용하지 않을 가능성이 크다.** N1은 미평가 상태로 두고 발명된 퍼센트/색등급을 금한다. 빈 필드를 카드에 나열하면 “평가됨”으로 오인되기 쉽다.
3. 형식적 우선순위 카테고리(긴급 등)를 **임상적으로 의미 있다 가정할 수 없다.** 멘토는 카테고리 이름 전에 현실 유스케이스 열거를 요구했다(M1). 임계값·가중·동점 규칙은 미승인(N1). 3건으로는 이득을 측정할 수 없다.

## (2) 멘토 요구사항 커버리지 매트릭스

상태: **충족 / 부분 / 미충족 / 해당없음(후속 팀안)**. 증거 ID만 사용. 멘토 발언을 창작하지 않음.

| 멘토 요구(M1) | 상태 | 근거 |
|---|---|---|
| 기능 확장 전 서비스 목표와 MUST REVIEW FIRST 기준 명확화 | 미충족 | 목표=우선순위 큐(N1) vs UI=뷰어(A1). MUST FIRST 기준·임계 미승인(N1) |
| 긴급 등 카테고리명 선정 전 현실 유스케이스 열거 | 미충족 | 카테고리 화면 없음(A1). 부서별 업무 미검증(N1) |
| 의미 있는 태그로 각 사례 선정 이유 제시 | 미충족 | 카드에 ID·슬라이스·GT 부피·검토대기만(A1). 순위 근거 없음 |
| 수치가 사용자에게 유용할 때만 노출 | 부분 | GT 부피 mL·슬라이스 수 노출(A1). 유용성 미검증. 점수 모델 없음(A2) |
| 패널/버튼/정렬/필터마다 한 문장 목적 | 미충족 | 목적 문장 보고 없음. 필터=전체/미검토/완료, 정렬=ID·GT부피(A1) |
| 아이콘은 임상의 검증 전까지 텍스트 | 미확인 | 아이콘 텍스트 정책 관찰 없음(A3). 가독성 미시각검토 |
| top10/20/30% = 임상 큐 vs 연구 작동점 모호성 해소 | 미충족 | 해당 UI 없음. N2는 동일 작업량 FN-capture 연구 서사를 여전히 제안 |
| 데이터/모델 증거와 주장 구분 | 부분 | 푸터 데이터 출처(A1). 그러나 제목/부제는 검토 서비스처럼 읽힘. 모델 없음(A2) |
| 다음 우선순위=사례 목록/분류 | 미충족 | 목록은 있으나 분류·카테고리 없음. 신워크플로 미구현(N1) |
| 소셜임팩트 서사 전 사용자 워크플로 확립 | 미충족 | 워크플로 미구현. 병리 참여는 사용자 결정이지 멘토 확인 아님(N2) |
| 전체 사례 유지 | 해당없음(후속 팀안, 멘토 승인 규칙 아님) | 필터가 안전성을 주장하지 말 것(N1). 현재 필터는 검토상태뿐(A1) |
| 구체 우선순위 규칙 | 해당없음(후속 팀안) | 임계/가중/동점 미승인(N1) |

계획 대 구현 추가 불일치(N1↔A1): CT 보기 게이트 없음, 초기 자동 뷰어, 점검 체크리스트 없음, 순위 근거 없음, 카테고리(크기/개수/분포) 없음. N2의 모델 불일치·경계·품질 단서·보정/홀드아웃/동결 임계는 **계획**이며 현재 정적 앱과 무관.

## (3) 우선순위 적대적 발견 (최대 10)

심각도: **치명 / 높음 / 중간**. 구현이 아니라 최소 수정 방향만.

**F1. 치명 — 제품 정체성 불일치 (큐 vs 브라우저)**  
증거: N1 목표=합리적 검토 우선순위 큐, 파일 브라우저 아님; A1 자동 뷰어·카테고리 없음·CT 보기 게이트 없음; 계획 “신워크플로 미구현”.  
위해: 멘토·심사·임상의가 뷰어를 우선순위 제품으로 오인. 이후 기능 확장이 잘못된 축(뷰어 완성도)으로 진행.  
최소 수정: 랜딩을 **사례 카드 목록**으로 고정. 뷰어는 명시 동작 후에만. 카피에서 “우선 검토”를 빼거나, 아직 없음을 한 문장으로 표시.  
시험: 초기 로드에 뷰어 DOM이 없고, 카드에 순위 근거 슬롯이 있는지. 주장은 카피와 불일치하면 실패.

**F2. 치명 — GT 부피 정렬을 우선순위로 오인 가능**  
증거: 정렬=사례 ID, GT 종양 부피순(A1); 전체 GT 부피 ≠ 최대 병변 직경·개별 병변 부담(A2); 크기≠치유가능, 다발성≠전이(N1).  
위해: 큰 전체 부피가 “먼저 볼 것”으로 읽힘. 작고 많은 병변, 분포, 실패 케이스가 뒤로 밀림. 연구 작동점을 임상 큐로 둔갑.  
최소 수정: 정렬 라벨을 「GT 전체 부피(연구용 탐색, 우선순위 아님)」으로. 우선순위 주장 문구 제거.  
시험: UI/카피에 “우선/긴급/큐”가 GT 부피와 결합되면 실패.

**F3. 높음 — 유스케이스·MUST REVIEW FIRST 없이 기능이 뷰어로 팽창**  
증거: M1 목표·기준 먼저; A1 슬라이더·휠·화살표·GT 토글·고정 윈도우는 있음. 기준은 없음.  
위해: 완성된 뷰어가 “진척”으로 오인되어 목록/분류가 계속 밀림.  
최소 수정: 뷰어 신규 조작을 멈추고 카드 필드(측정, 점검, 선정 이유)만 채울 것.  
시험: 카드에 선정 이유 1문장과 측정 항목이 없으면 마일스톤 미달.

**F4. 높음 — CT 보기 게이트 부재, 초기 자동 뷰어**  
증거: N1 클릭 CT 보기만, 초기 자동 뷰어 금지; A1 초기 로드에 뷰어 가시.  
위해: 목록 비교·분류가 불가능. 병리 사용자는 CT-only 진단처럼 오해(N2: 의도 아님).  
최소 수정: 기본 화면=목록. 「CT 보기」는 매칭된 CT만.  
시험: 첫 페인트에 뷰어 없음; 버튼 후에만 해당 ID CT.

**F5. 높음 — 3건 양성례만으로 큐의 존재 이유 붕괴**  
증거: 75/123/74슬라이스 병변 양성 3건, 음성/정상/처리실패 없음(A2).  
위해: 필터·정렬·우선순위가 차이를 만들 수 없음. “전부 병변 있음”이면 큐가 불필요. 유한 3건으로 이득 측정 불가.  
최소 수정: 주장 범위를 「양성 공개 3건 뷰어 데모」로 축소. 음성·실패는 카피에서 “없음”으로 명시.  
시험: 코호트 구성이 UI/푸터에 표시되는가. 이득 수치 주장 시 즉시 실패.

**F6. 높음 — 검토 완료가 감사 가능한 임상 행위처럼 보임**  
증거: 검토 완료 버튼, 검토대기, 필터 미검토/완료; persistence=브라우저 로컬, 인증 저자·감사추적 없음(A1).  
위해: “완료”가 안전·책임 이전으로 오인. N1: 필터가 안전을 주장하지 말 것.  
최소 수정: 「이 브라우저에서 표시만 숨김 (기록 아님)」. 완료를 임상 상태처럼 쓰지 말 것.  
시험: 완료/필터 카피에 안전·책임 함의 있으면 실패.

**F7. 중간 — 카드가 승인된 정보 구조를 충족하지 않음**  
증거: 필요=원본 비식별 사례 ID, 측정, 점검 체크리스트, 순위 근거(N1). 실제=ID, 총슬라이스, GT 부피 mL, 검토대기(A1). 개수/분포 없음(A2).  
위해: 왜 이 순선인지 설명 불가. 멘토의 “의미 있는 태그” 미달.  
최소 수정: 측정(전체부피임을 명시), 점검(평가 전), 근거(현재는 “GT 부피 탐색만일 수 있음”) 슬롯. 빈 임상 등급 금지.  
시험: 카드에 근거 문장과 측정 출처(GT vs 모델) 구분.

**F8. 중간 — 계획 잔여 연구 서사(모델 불일치, FN-capture, top%)가 현재 앱과 혼선**  
증거: N2 잔존 제안 vs 정적 앱; M1 top% 모호성; 효능·홀드아웃 순위 평가 없음(N1).  
위해: 발표가 미래 모델을 현재 기능처럼 말하게 됨.  
최소 수정: 문서/UI를 **현재 / 계획 / 금지된 주장** 3단으로 분리.  
시험: 현재 화면에 모델·불확실성·FN 이득 수치가 있으면 실패.

**F9. 중간 — 영상의학 기본 조작이 고정·미검증**  
증거: 고정 W400/L50, 축상만, 오버레이 기본 켜짐, 전역 11–14px, 대비율 미검토(A1, A3). MD 사용성 연구 없음.  
위해: 간 CT에서 고정 윈도우는 병변 가시성을 왜곡할 수 있음(**가설**, 본 패킷은 시각 미검토). 작은 글자는 목록 비교를 해침.  
최소 수정: 윈도 프리셋 라벨과 “고정, 미검증” 표기. 카드 타이포를 뷰어보다 우선.  
시험: 윈도 변경 불가/미표기면 경고. 가독성은 MD 1회 관찰 전 “검증됨” 금지.

**F10. 중간 — 의도 사용자(영상 vs 병리)와 UI가 단일 뷰어로 붕괴**  
증거: 초기 사용자=영상 MD·병리 MD, 부서 업무 미검증(N1); CT-only 병리 진단 비의도(N2); 부제=CT와 주석 함께 확인(A1).  
위해: 병리에게 부적합한 1차 화면. 영상에게는 우선순위 없는 뷰어. 둘 다 실패.  
최소 수정: 역할 선택 없이 **공통 목록**만. 병리용 진단 카피를 넣지 말 것.  
시험: 병리 진단·치유/전이 확정 표현 있으면 실패.

## (4) 영상의학 vs 병리 워크플로, 실제 효용 대안

**확인.** 부서별 과업은 미검증(N1). 병리 참여는 멘토 확인이 아님(N2).

**영상의학(합리적 가설).** 실제 큐는 미판독 워크리스트, 임상 정보, 이전 검사, PACS, 재구성, 윈도/MPR이 전제다. 현재는 공개 3건 GT 오버레이 축상 뷰어. **가까운 효용:** (a) 데이터 품질·방향·ID 정합 확인, (b) GT 탐색 교육, (c) 카드 카피 실험. **가깝지 않은 효용:** 판독 우선순위, 예후, 치유가능성.

**병리.** CT만으로 병리 진단이 의도가 아니다(N2). 병리의 “우선 검토”는 대개 유리·디지털 슬라이드·육안·임상 의뢰 맥락이다. CT 주석 뷰어는 병리 1차 도구가 되기 어렵다. **대안:** 병리를 초기 사용자에서 빼거나, “영상 소견을 병리 의뢰 전에 같은 카드로 공유하는 읽기 전용 목록” 정도로 범위를 줄인다. 전이/치유 필드를 병리 확정처럼 두지 않는다.

**플레이스홀더 전부 노출은 비추천.** 평가 전 라벨만 남기고, 크기→치유, 다발→전이 추론을 UI가 수행하지 말 것(N1).

## (5) UX 상호작용 제안 (카드·카테고리 → 온디맨드 CT)

구현 명세가 아니라 상호작용 원칙.

1. **1화면=전체 사례 가시 목록.** 필터는 숨김이지 삭제/안전 선언이 아님. “Keep all”은 멘토 승인 규칙이 아니므로, 숨김의 의미를 한 문장으로.
2. **카드 1순위 정보:** 원본 사례 ID, GT 측정(전체 부피임을 명시), 개수/분포는 **측정되었을 때만**, 선정 이유 1문장, 점검=평가 전. 점수·색등급·% 금지(유용성 입증 전).
3. **카테고리는 이름부터 만들지 말 것.** 유스케이스 태그 예: 「GT 탐색용 양성례」, 「측정 미완」, 「코호트 비대표」. “긴급”은 유스케이스 합의 전 사용 금지(M1).
4. **CT는 게이트.** 「CT 보기」→ 해당 ID만. 초기 오버레이 on/off는 사용자 선택. 인간 통제: 주석 숨김, 소스 푸터, GT vs 모델 구분.
5. **미해결 임상 라벨**은 공란+「평가 전」. 채우기 전에는 정렬 키로 쓰지 않음.
6. **프로비넌스:** 데이터 범위 푸터 유지(A1). 헤더 메트릭(3건, 0검토, 272슬라이스)은 “데모 규모”로 읽히게.
7. **모든 컨트롤 한 문장 목적.** 아이콘+텍스트. 수치 남발 금지.

## (6) “우선순위” 주장 전 반드시 검증할 것

병원급 시스템 요구가 아니다. **주장하는 문장 단위**로 검증한다.

**주장 금지 조건(현재).** 홀드아웃 순위 평가·임상의 수용·효능·수요 없음(N1). 모델 없음(A2). 3건 양성(A2).

**우선순위 주장 전 최소 검증(프로토타입 범위).**
- **정의:** MUST REVIEW FIRST가 누구의 어떤 결정인지 한 문장. 임상 큐 vs 연구 작동점 분리(M1).
- **기준선:** 무작위 순서, 도착순, ID순, (연구라면) GT 부피순. 부피순을 임상 기준선으로 부르지 말 것.
- **실패 모드:** 음성/정상, 처리 실패, GT-모델 불일치, 소병변·다발, 분포만 이상, 동점. 지금 코호트는 이 실패를 **관찰할 수 없다**.
- **GT 파생 측정 ≠ 전향 우선순위.** 전향이란 배포 입력(영상±모델)만으로 순서를 정하고, 이후 인간 판정과 비교하는 것이다. GT로 순서를 정하면 정보 누수다.
- **카테고리 의미:** 임상의가 같은 카드를 보고 같은 다음 행동을 하는가. 가정 금지.
- **플레이스홀더:** 빈 임상 필드가 결정에 도움이 되는지, 방해인지. 도움이 아니면 숨김.

3건으로 AUC·워크로드 이득·top% 포착을 말하지 말 것.

## (7) 최소 단계 개선과 멘토/MD 질문 5

병원 통합·인증·대규모 평가를 1단계에 넣지 않는다.

**단계 0 (주장 교정).** 현재=정적 3건 뷰어. 우선순위·효능 문장 삭제. GT 부피=탐색 키.

**단계 1 (멘토가 다음이라고 한 목록/분류).** 자동 뷰어 제거. 카드에 ID·측정 출처·점검 평가 전·선정 이유. 컨트롤 목적 문장. CT 보기 게이트. 완료=로컬 표시.

**단계 2 (유스케이스 후 카테고리).** 영상 MD와 “먼저 볼 실패 유형”만 인터뷰. 이름(긴급 등)은 그 다음. 임계·가중 발명 금지.

**단계 3 (모델이 실제로 있을 때만).** GT 탐색과 배포 큐를 화면에서 분리. 연구 작동점은 연구 패널에만.

**묻기 (상위 5).**
1. MUST REVIEW FIRST의 사용자는 누구이며, 그 결정의 대안(지금 무엇을 보는가)은 무엇인가?
2. 카테고리 이름 전에 합의된 **현실 유스케이스 3개**는 무엇인가? 없는가?
3. GT 부피 정렬을 제품에 남길 가치가 있는가, 아니면 연구 디버그인가?
4. 병리 MD는 이 목록에서 **무엇을 결정**하는가? 결정이 없으면 왜 초기 사용자인가?
5. 수치(부피, 슬라이스, 이후 점수)가 없으면 못 쓰는가, 있으면 오인하는가?

## 마무리: 변경 3가지와 본 검토의 한계

**지금 바꿀 것 3.**
1. 제품을 뷰어가 아니라 **게이트된 카드 목록**으로 재프레이밍하고, 우선순위 주장을 제거하거나 “미구현”으로 표시.
2. GT 전체 부피를 **우선순위가 아닌 탐색 키**로 명시하고, 치유/전이/긴급 발명을 넣지 말 것.
3. 코호트 한계(양성 3건, 모델 없음, 로컬 토글)를 헤더/푸터에서 숨기지 말 것.

**본 검토의 한계.** 전사 요약·계획 요약·부모 관찰 UI/DOM 기술만 사용했다. 대비·미학·실제 클릭 동선은 미확인(A3). 임상 타당성·병변 가시성·윈도 적합성은 가설이다. 멘토 원음원·승인 임계·임상의 발화는 창작하지 않았다. 3건으로 이득을 추정하지 않았다. 이는 임상 검증이 아니다.
