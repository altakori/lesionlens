## 왜 늘렸나
1차 확장(5→13건)에서 "절편 수가 크다"는 이유로 뺀 093·088·095·113·020과, 감사만 하고 넣지
않은 009·019·026·065·080·083·102·126·129를 전부 앱으로 옮겼다. 이제 **이 코호트의 27건 = 감사한
27건과 같은 집합**(case_045는 모델 산출물이 없는 별도 사례)이므로, 발표의 사실 표와 화면이
같은 사례를 가리킨다. 이후 lv2 신규 14건이 더해 현재 앱 큐는 41건이다(`docs/lv2-test20-cohort.md`).

- 1차: case_005·049·051·057·060·061·079·116 (5건 → 13건)
- 2차: case_009·019·020·026·065·080·083·088·093·095·102·113·126·129 (13건 → **27건**)
- 매니페스트: `lits-model-compare-v3`, 27건, 12,055 절편, 60,053개 자산(CT webp 12,055 + 모델 오버레이 3종 36,165, case_045는 오버레이 없음)
- 현재 매니페스트는 `lits-model-compare-v4`(41건, 20,142 절편, 92,401개 자산). 아래 27건/30건 수치는 **이 코호트 편입까지의 기준값**이고, v4에서 변경된 것은 신규 사례 추가뿐이다.

## 제외: case_086 (26/27만 앱에 들어감)
LiTS 라벨 특유의 float32 반올림으로 GT affine이 `-0.6835938096`, CT affine이 `-0.68359375`.
`prepare_model_compare.canonical_arrays()`는 마스크와 CT의 affine **완전 일치**를 요구하므로
case_086은 빌드 단계에서 거부된다. 가드 자체를 완화하지 않았고(완화하면 z축 정렬 보장을 잃는다),
reasons가 2에 불과한 사례를 위해 발표 직전 안정성 리스크를 올리지는 않았다.
후보 처리: (a) 오버레이만 GT 기준으로 재표현, (b) 가드를 `allclose(atol=1e-6)`로 문서화된
임계값 완화 후 회귀 테스트 추가. 둘 다 발표 동결 이후 결정.

## 앱에 미치는 영향 (측정 필요 항목은 표시)
- 이 코호트 편입까지 큐 카드 27건(+ 합성 DEMO 1건). GT 부피 내림차순 정렬 1위는 case_129(664.6 mL).
- 이 코호트 편입까지 `md-core.js` 검사 receipt 30건(사례 27 + LL-CT 3). 현재는 44건(사례 41 + LL-CT 3). imageSha256 기준 중복 판정은
  case_000↔LL-CT-001, case_045↔LL-CT-002 두 쌍만 의도된 중복이며 신규 14건은 고유하다.
- 매니페스트 v3는 **compact JSON**(들여쓰기·공백 제거)으로 저장한다 → 10,090,462바이트(9.62MB).
  같은 내용을 들여쓰기 JSON으로 쓰면 13,099,351바이트다. 파일 크기는 사례 수보다 **직렬화 방식**에
  더 민감하므로, 오프라인 배포 시에는 자산(webp)을 포함한 총 패킷 크기로 관리한다.
- 검증: `prepare_model_compare.build()`가 소스 해시·기하를 재확인하고 자산을 재생성,
  `compare_manifest.validate_manifest()`가 27건 스키마·보셀 수를 다시 계산해 통과.
  앱측 `app.js`도 같은 등록부(CASE_SPECS 27·MODEL_VOXELS 26)로 자체 검증.

## 한계 (발표에서 함께 말해야 하는 것)
- arm 출력은 raw + canonical 후처리만 적용(최소 객체 크기 제거 없음). 임상 후처리가 아니다.
- GT는 LiTS 단일 어노테이션 → 정답으로 과장하지 않는다.
- 모델 성능 우월·임상 효과 주장은 이 run의 claim boundary와 맞지 않는다.
- 환자당 CT 1건이므로 "같은 환자의 이전·다음 CT"는 여전히 없다(시리즈는 검사 식별 receipt 기준).
- 12,055 절편을 엄격 서버(`scripts/serve_integrated.py`)로 띄우면 시작 시 전량 재검증으로
  오래 걸린다. 실연은 정적 서빙, 엄격 검증은 발표 전 1회 무결성 점검용으로 쓴다.
- 환자 식별자·DICOM 태그는 이 프로젝트에 들어오지 않았다. 원격은 승인 별명 읽기 전용.
